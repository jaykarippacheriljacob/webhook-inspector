The structure

webhook-inspector/
├── app/
│   ├── __init__.py        marks "app" as a package
│   ├── config.py          settings from environment variables
│   ├── storage.py         in-memory store (ring buffer + idempotency cache)
│   ├── rate_limit.py      sliding-window rate limiter
│   ├── capture.py         turns a Request into a saveable record
│   ├── security.py        bearer-token auth (401 vs 403)
│   ├── dashboard.py       the live HTML page
│   └── routers/
│       ├── __init__.py    marks "routers" as a package
│       ├── webhook.py     the /webhook endpoint
│       └── inspect.py     the /requests routes + /health
├── requirements.txt
├── Procfile
├── render.yaml
├── .gitignore
└── README.md

The idea behind the split: each file has one job. Settings live in config; storing lives in storage; the HTTP rules (rate limit, auth, capture) each get their own file; and the routes (routers/) just wire those pieces together. That's what says “I know separation of concerns.” You start it with uvicorn app.main:app (note the app. prefix) because the code lives in the app/ package.

File 1 / 9

app/config.py

What it does The one place that reads environment variables. Every other file imports its settings from here instead of calling os.getenv itself.

Why its own file Centralised config is a real-world pattern — change a default in one spot, and you can see at a glance everything the app is tunable on.

"""
Configuration for the whole app, read once from environment variables.

Keeping this in one place means no other file calls os.getenv — they import
from here. Everything is optional and has a sensible default.
"""
import os

# If set, /webhook requires  Authorization: Bearer <API_TOKEN>
API_TOKEN = os.getenv("API_TOKEN")

# If set, DELETE /requests/{id} requires  Authorization: Bearer <ADMIN_TOKEN>
ADMIN_TOKEN = os.getenv("ADMIN_TOKEN")

# Max /webhook requests per minute, per client IP, before a 429
RATE_LIMIT = int(os.getenv("RATE_LIMIT", "60"))

# How many captured requests to keep in memory (a ring buffer)
MAX_STORED = int(os.getenv("MAX_STORED", "100"))

Line by line

  • os.getenv("NAME", "default") means “look for a setting called NAME set outside the code; if it isn't there, use this default.” That's how you change behaviour when you deploy without editing code.
  • API_TOKEN — an optional password for /webhook. Set it and callers must send it; leave it unset and the endpoint is open.
  • ADMIN_TOKEN — a second optional password, only for deleting captured requests (a destructive action, so its own key).
  • RATE_LIMIT — max requests one visitor may send per minute (default 60) before a 429.
  • MAX_STORED — how many captured requests to keep at once (default 100); the oldest drops off after that.
  • int(os.getenv("RATE_LIMIT", "60")) — env vars are always text, so we wrap it in int(...) to get a number.

Keep this The top four are just labelled boxes holding a value; os.getenv decides whether each gets your custom value or the built-in default. (Also create app/__init__.py with a single docstring line — it just marks the folder as a Python package.)

File 2 / 9

app/storage.py

What it does The app's memory — where every captured request is kept, and where the idempotency cache lives.

Why its own file “How we store things” is separate from “what the endpoints do.” If you ever swapped the in-memory store for a real database, this is the only file you'd rewrite.

"""
In-memory storage for captured requests, plus the idempotency cache.

There is no database on purpose: an inspector wants a fresh slate on restart.
A deque with maxlen is a ring buffer — once it is full, adding a new item
drops the oldest automatically, so memory can never grow without bound.
"""
from collections import deque

from app.config import MAX_STORED

# Newest request first. maxlen makes it self-trimming.
requests_log: deque = deque(maxlen=MAX_STORED)

# Idempotency-Key -> the record we returned the first time we saw that key.
idempotency_cache: dict = {}


def add(record: dict) -> None:
    requests_log.appendleft(record)


def all_records(limit: int = 50) -> list:
    return list(requests_log)[:limit]


def find(req_id: str):
    for record in requests_log:
        if record["id"] == req_id:
            return record
    return None


def remove(req_id: str) -> bool:
    record = find(req_id)
    if record is None:
        return False
    requests_log.remove(record)
    return True


def count() -> int:
    return len(requests_log)

Line by line

  • deque (“deck”) — a list you can add to / remove from at either end, fast. We always add to the front (newest first).
  • maxlen=MAX_STORED — the ring-buffer trick: cap it at 100 and the oldest falls off automatically. No cleanup code needed.
  • idempotency_cache = {} — a dictionary (key→value lookup table). Key = the Idempotency-Key header, value = the request we saved for it.
  • The five functions are named shortcuts the rest of the app calls: add (put on front), all_records (recent ones), find (by id, or None), remove (delete, returns True/False), count.
  • -> None, -> list, -> bool are type hints — documentation of what a function returns; they don't change behaviour.

Keep this Everything about storing is behind simple verbs (add, find, remove). The endpoints never touch the deque directly — that's what makes it easy to change later.

File 3 / 9

app/rate_limit.py

What it does Stops one visitor from flooding /webhook. Answers a single yes/no: has this IP hit its limit this minute?

Why its own file Rate limiting is a self-contained rule with its own little memory; the webhook route just asks is_rate_limited(ip) without caring how it's decided.

"""
A tiny in-memory sliding-window rate limiter.

For each IP we keep the timestamps of its recent hits. On each call we drop
timestamps older than 60 seconds; if what remains is already at the limit,
the caller is limited. Simple, no dependencies — good enough for a demo and
enough to talk about the idea in an interview.
"""
import time
from collections import defaultdict

from app.config import RATE_LIMIT

_buckets: dict = defaultdict(list)  # ip -> [timestamps within the last minute]


def is_rate_limited(ip: str) -> bool:
    now = time.time()
    recent = [t for t in _buckets[ip] if now - t < 60]
    _buckets[ip] = recent
    if len(recent) >= RATE_LIMIT:
        return True
    recent.append(now)
    return False

Line by line

  • time.time() — “now” as a number of seconds; later is a bigger number, so you can measure gaps.
  • defaultdict(list) — a dict that hands you an empty list the first time you look up a key, so _buckets[ip] always works even for a brand-new visitor.
  • The leading underscore in _buckets is a convention meaning “private — don't use from outside this file.”
  • recent = [t for t in _buckets[ip] if now - t < 60] is a list comprehension: keep only timestamps from the last 60 seconds. That's the “sliding window.”
  • If the window already holds RATE_LIMIT hits → return True (limited); otherwise record this hit and return False (allowed).

Keep this Each visitor gets a rolling one-minute window; old hits silently disappear. On True, the webhook route returns a 429.

app/capture.py

What it does The heart of the inspector: takes a raw incoming request and turns it into a tidy dictionary — method, path, query, headers, body, plus an id and timestamp.

Why its own file “How we read a request” is a reusable skill separate from any one route. The small client_ip helper lives here too.

"""
Turn an incoming Request into a plain dict we can store and return as JSON.

This is the heart of the "inspector": it reads the method, path, query,
headers and body, and stamps each capture with an id and a timestamp. The
Authorization header is masked so a real secret is never stored or echoed.
"""
import uuid
from datetime import datetime, timezone

from fastapi import Request


def client_ip(request: Request) -> str:
    """Real client IP, honouring a proxy's X-Forwarded-For if present."""
    forwarded = request.headers.get("x-forwarded-for")
    if forwarded:
        return forwarded.split(",")[0].strip()
    return request.client.host if request.client else "unknown"


async def capture(request: Request) -> dict:
    raw = await request.body()
    try:
        body = raw.decode("utf-8")
    except UnicodeDecodeError:
        body = f"<{len(raw)} bytes of binary data>"

    headers = dict(request.headers)
    if "authorization" in headers:                      # never echo a full secret
        headers["authorization"] = headers["authorization"][:12] + "…(masked)"

    return {
        "id": uuid.uuid4().hex[:8],
        "received_at": datetime.now(timezone.utc).isoformat(),
        "method": request.method,
        "path": request.url.path,
        "query": dict(request.query_params),
        "headers": headers,
        "body": body,
        "client_ip": client_ip(request),
    }

Line by line

  • uuid — uuid.uuid4().hex[:8] makes a random id and takes the first 8 chars (e.g. 0825b571) to label each capture.
  • datetime.now(timezone.utc).isoformat() — “right now, in UTC, as text”. UTC (not local time) keeps timestamps consistent wherever the server runs.
  • Request — FastAPI's object holding everything about the incoming call.
  • async def / await — the one new concept. Reading the body can take a moment, so await request.body() means “pause here until it arrives, without freezing the server for others.”
  • try / except UnicodeDecodeError — try to read the body as text; if it's binary that would error, so we catch it and store a friendly note instead of crashing.
  • Masking — the authorization header is replaced with its first 12 chars + “…(masked)”, so you can see it was sent without ever storing the real secret.
  • The big return {...} builds the final record — a dictionary of label→value pairs — which is what gets stored and shown.

Keep this Raw request in → clean, safe dictionary out. It stores nothing and decides nothing; it just reads and packages.

app/security.py

What it does One small function that checks a bearer token and decides whether to let the request through. Where the 401-vs-403 distinction lives.

Why its own file Auth is a rule more than one route needs (both /webhook and DELETE). Write it once here — one place to change it.

"""
Bearer-token authentication.

One helper, used by any route that wants protecting. It encodes the
difference interviewers love to test:
  - no / malformed credentials  -> 401 Unauthorized  ("who are you?")
  - credentials that don't match -> 403 Forbidden     ("you can't do this")
If `expected` is None the check is skipped, so auth is opt-in per deployment.
"""
from typing import Optional

from fastapi import HTTPException


def require_token(authorization: Optional[str], expected: Optional[str]) -> None:
    if not expected:                       # auth disabled for this token
        return
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(status_code=401, detail="Missing or malformed Authorization header.")
    if authorization.removeprefix("Bearer ").strip() != expected:
        raise HTTPException(status_code=403, detail="Token not accepted for this resource.")

Line by line

  • Optional[str] — “either text or nothing (None).” Both inputs can be missing.
  • HTTPException + raise — raise stops the request immediately and FastAPI sends back that status code; the rest of the route never runs.
  • Gate 1 — if not expected: return: if the token isn't configured, auth is off for this route (opt-in).
  • Gate 2 — no / malformed Authorization header → 401 (“who are you?”).
  • Gate 3 — well-formed but wrong token → 403 (“I know you, but you can't”). removeprefix("Bearer ") strips the word to get the token; != means “not equal.”

Keep this Great interview line: 401 is “I don't know who you are,” 403 is “I know who you are, but you're not allowed.” This tiny file proves you understand authentication vs. authorization.

Keep this The dashboard is a client of your own API: Python serves data at /requests; this page fetches it every 2s and paints it. Backend and frontend over HTTP — the whole point, in one file.

File 7 / 9

app/routers/webhook.py

What it does The /webhook endpoint — the one you point real webhooks at. Notice how short it is: it calls the pieces from Files 2–5 in the right order.

Why its own file A “router” is a group of related routes. Keeping /webhook separate from the /requests routes means each file is about one part of your API.

"""
The /webhook receiver — the endpoint you point real webhooks at.

It accepts any common method, then runs three gates in order before storing:
  1. rate limit   -> 429
  2. auth         -> 401 / 403
  3. idempotency  -> replay the first result instead of duplicating
and finally returns 201 Created with an echo of what it captured.
"""
from typing import Optional

from fastapi import APIRouter, Request, Header
from fastapi.responses import JSONResponse

from app import config, storage
from app.capture import capture, client_ip
from app.rate_limit import is_rate_limited
from app.security import require_token

router = APIRouter()


@router.api_route("/webhook", methods=["GET", "POST", "PUT", "PATCH", "DELETE"])
async def receive_webhook(
    request: Request,
    authorization: Optional[str] = Header(default=None),
    idempotency_key: Optional[str] = Header(default=None),
):
    # 1) rate limiting
    if is_rate_limited(client_ip(request)):
        return JSONResponse(
            status_code=429,
            content={"error": "rate_limited",
                     "detail": f"Limit is {config.RATE_LIMIT} requests per minute."},
            headers={"Retry-After": "60"},
        )

    # 2) authentication (only if API_TOKEN is configured)
    require_token(authorization, config.API_TOKEN)

    # 3) idempotency: a repeated key returns the first result, never a duplicate
    if idempotency_key and idempotency_key in storage.idempotency_cache:
        prior = storage.idempotency_cache[idempotency_key]
        return JSONResponse(status_code=200, content={"idempotent_replay": True, **prior})

    record = await capture(request)
    storage.add(record)
    if idempotency_key:
        storage.idempotency_cache[idempotency_key] = record

    return JSONResponse(status_code=201, content={"captured": True, **record})

Line by line

  • APIRouter() — a mini-app you attach routes to; main.py “includes” it later. How FastAPI splits routes across files.
  • @router.api_route("/webhook", methods=[...]) — a decorator registering this function as the handler; api_route lets one handler accept several methods (what makes it a true inspector).
  • authorization: Optional[str] = Header(default=None) — FastAPI reads the header off the request and hands it in as a parameter; default None if missing. Same for Idempotency-Key.
  • JSONResponse(status_code=..., content=..., headers=...) — lets you set a specific status code, body and extra headers (used for 429, 200 replay, 201).
  • {"captured": True, **record} — **record is dictionary unpacking: spread all the record's pairs into a new dict alongside the flag.
  • Flow (order matters): 1) rate limit → 429; 2) auth → 401/403; 3) idempotency → 200 replay; else capture + store + 201 Created.

Keep this A good route is thin: it decides order and status codes but delegates the real work to the small files you already wrote.

File 8 / 9

app/routers/inspect.py

What it does The endpoints for reading and managing captures — list, fetch one, delete one, plus /health. The dashboard calls /requests here.

Why its own file These routes are all about inspecting stored data — a different job from receiving webhooks — so they get their own router.

"""
Read and manage what /webhook captured, plus a health check.

GET routes only read (safe + idempotent); DELETE mutates and returns 204.
DELETE is treated as privileged: if ADMIN_TOKEN is set it must be presented.
"""
from typing import Optional

from fastapi import APIRouter, Header, HTTPException, Response

from app import config, storage
from app.security import require_token

router = APIRouter()


@router.get("/requests")
def list_requests(limit: int = 50):
    return {"count": storage.count(), "requests": storage.all_records(limit)}


@router.get("/requests/{req_id}")
def get_request(req_id: str):
    record = storage.find(req_id)
    if record is None:
        raise HTTPException(status_code=404, detail="No captured request with that id.")
    return record


@router.delete("/requests/{req_id}", status_code=204)
def delete_request(req_id: str, authorization: Optional[str] = Header(default=None)):
    require_token(authorization, config.ADMIN_TOKEN)
    if not storage.remove(req_id):
        raise HTTPException(status_code=404, detail="No captured request with that id.")
    return Response(status_code=204)


@router.get("/health")
def health():
    return {"status": "ok", "stored": storage.count()}

Line by line

  • @router.get(...) / @router.delete(...) — single-method versions of api_route; cleaner when a route is just one method.
  • def (not async) — these don't await anything (just read memory), so they don't need to be async. FastAPI handles both.
  • limit: int = 50 — a query parameter: an argument with a default; FastAPI reads it from the URL (/requests?limit=10) and converts it to int.
  • {req_id} in the path + req_id: str — a path parameter: whatever's in that URL slot arrives as the argument. How you address one item.
  • Response(status_code=204) — 204 No Content = “success, nothing to send back,” the right reply to a delete.
  • Routes: list_requests (count + records, read-only), get_request (find or 404), delete_request (auth → remove → 204, or 404), health (an “am I alive?” ping deploy platforms use).

Keep this Mirrors real REST design: a collection (/requests) and items within it (/requests/{id}), with the method choosing the action — GET reads, DELETE removes.

File 9 / 9

app/main.py

What it does The entry point uvicorn runs. Deliberately tiny: it creates the app, attaches the two routers, and serves the dashboard at /.

Why its own file The shortness is the point — main.py reads like a table of contents; a reviewer sees the whole shape of the app in ten lines.

"""
Application entry point.

This file stays tiny on purpose: it creates the FastAPI app, mounts the two
route groups, and serves the dashboard at /. Run it with:

    uvicorn app.main:app --reload
"""
from fastapi import FastAPI
from fastapi.responses import HTMLResponse

from app.dashboard import DASHBOARD_HTML
from app.routers import inspect, webhook

app = FastAPI(title="Webhook Inspector", version="1.0.0")

app.include_router(webhook.router)
app.include_router(inspect.router)


@app.get("/", response_class=HTMLResponse)
def dashboard():
    return DASHBOARD_HTML

Line by line

  • app = FastAPI(...) — the application object the whole project is built around; the run command points at it (app.main:app = the app variable inside app/main.py).
  • app.include_router(webhook.router) — the payoff of splitting routes: each router is plugged in with one line. New feature later = new router file + one more include line; you never touch the existing ones.
  • @app.get("/", response_class=HTMLResponse) — the homepage. response_class=HTMLResponse tells FastAPI “this is a web page, not JSON,” so the browser renders it instead of showing raw text.
  • def dashboard(): return DASHBOARD_HTML — a plain function (no waiting). Its name is just a label; the @app.get("/") decorator is what maps it to the URL. It returns the page string from File 6.

Keep this main.py wires, it doesn't work. Config, storage, the HTTP rules and the routes each live in their own file; main.py just connects them.

How they connect

  1. A request to /webhook flows: main.py routes it → routers/webhook.py handles it → which calls rate_limit → security → capture → storage, using values from config.
  2. Meanwhile the browser loads main.py's / → gets dashboard.py's page → which polls routers/inspect.py's /requests every 2s → reading from storage.

Every file has one job, and main.py is the map. The dashboard is a client of your own API — backend and frontend talking over HTTP, which is the whole point of the project.

Run & test it — macOS, step by step

Everything runs in the Terminal, from inside your webhook-inspector folder. Each step says exactly what you should see.

0 · Check Python 3 is installed

python3 --version

See: something like Python 3.11+. If it says “command not found”, run xcode-select --install, finish the popup, then try again.

1 · One-time setup — make the sandbox & install libraries

python3 -m venv .venv
source .venv/bin/activate
pip install fastapi "uvicorn[standard]"

See: your prompt now starts with (.venv), and pip installs without red errors. Rule to remember: every new Terminal window needs source .venv/bin/activate before uvicorn works.

2 · Start the server

uvicorn app.main:app --reload --reload-dir app

See: Application startup complete. and Uvicorn running on http://127.0.0.1:8000. The --reload-dir app stops it from watching the .venv folder (which otherwise causes an endless “Reloading…” loop).

3 · Open the dashboard

In your browser, go to http://localhost:8000. See: the dark “Webhook Inspector” page saying “Waiting for the first request…”. Leave it open — it refreshes every 2 seconds.

4 · Send requests (a second Terminal; curl needs no venv)

curl -X POST http://localhost:8000/webhook -H "Content-Type: application/json" -d '{"event":"order.created","id":42}'
curl "http://localhost:8000/webhook?source=n8n&test=1"
curl http://localhost:8000/requests

See: each command returns JSON, and a card appears on the dashboard within 2s — green for POST, blue for GET. The GET one shows its query as {"source":"n8n","test":"1"}.

5 · Watch the status codes (the -i flag shows them)

curl -i -X POST http://localhost:8000/webhook -d '{}'      # expect 201 Created
curl -i http://localhost:8000/requests/nope           # expect 404 Not Found
# copy a real id from /requests, then:
curl -i -X DELETE http://localhost:8000/requests/PUT_ID_HERE   # expect 204 No Content

See: the first line of each reply — HTTP/1.1 201 Created, 404 Not Found, 204 No Content (204 deliberately has no body).

6 · Idempotency — the “no duplicates” trick

curl -X POST http://localhost:8000/webhook -H "Idempotency-Key: abc-123" -d '{"charge":"once"}'
# now run the exact same line a second time

See: the first reply has "captured": true; the second has "idempotent_replay": true with the same id — and only ONE card on the dashboard. That is the “a webhook fired twice” problem, solved.

7 · Rate limiting → 429 (optional)

# stop the server with Ctrl+C, then start it with a low limit:
RATE_LIMIT=5 uvicorn app.main:app
# in another terminal, fire 8 quick requests:
for i in $(seq 1 8); do curl -s -o /dev/null -w "%{http_code}\n" -X POST localhost:8000/webhook -d '{}'; done

See: the first five print 201, then 429 once you cross the limit.

8 · Auth — 401 vs 403 (optional)

# stop the server, then require a token:
API_TOKEN=secret123 uvicorn app.main:app
curl -i -X POST localhost:8000/webhook -d '{}'                                   # 401 — no token
curl -i -X POST localhost:8000/webhook -H "Authorization: Bearer wrong" -d '{}'     # 403 — wrong token
curl -i -X POST localhost:8000/webhook -H "Authorization: Bearer secret123" -d '{}' # 201 — correct

See: 401 → 403 → 201. And on the dashboard, the Authorization header shows as Bearer secre…(masked) — the secret is never stored.

9 · Stop the server

Press Ctrl+C. See: Application shutdown complete.

If something goes wrong

  • command not found: pip / uvicorn → the venv isn't active in this terminal. Run source .venv/bin/activate (the prompt should show (.venv)).
  • command not found: python3 → install it with xcode-select --install.
  • endless “Reloading…” → add --reload-dir app, or drop --reload entirely.
  • Address already in use → port 8000 is busy; use another: uvicorn app.main:app --port 8001.

Glossary — the terms to know cold

async / await
Marks work that waits on something external (like reading a request body) so the server can serve others meanwhile. You await the slow thing.
decorator (@)
A line just above a function that changes or registers it. @app.get("/") registers the function as the handler for that route.
APIRouter
A group of routes in its own file, plugged into the app with include_router. Keeps related endpoints together.
Header(default=None)
Tells FastAPI to pull a named HTTP header off the request and pass it into your function as an argument.
path parameter
A slot in the URL, like /requests/{id}, delivered to your function as an argument. Addresses one specific item.
query parameter
A value after ? in the URL, like ?limit=10. A function argument with a default; FastAPI reads and type-converts it.
HTTPException / raise
raise HTTPException(status_code=...) stops the request and returns that error code immediately.
deque
A double-ended list; with maxlen it's a self-trimming ring buffer (old items drop off).
defaultdict(list)
A dictionary that auto-creates an empty list for any new key, so lookups never fail.
dict unpacking (**)
{**a, "x": 1} spreads all of dict a's pairs into a new dict.
type hint (-> str)
A note saying what a value/return is. Documentation for humans and editors; doesn't change behaviour.
JSONResponse / Response
Return objects that let you set the exact status code, body and headers of a reply.
